Migrate V1 research insights → Scholar-ID-keyed

Reads the old data/scholar-insights.json.enc (V1, name-keyed), resolves each name to a Master Scholar ID using Family/Given/Scholar Name, and produces four buckets:

  • MATCHED — unambiguous name resolution, auto-migrated with full fidelity (keywords, summary HTML, hyperlinks, sources).
  • AMBIGUOUS — name matches two or more Master rows; kept aside for your review, never discarded.
  • UNMATCHED — name resolves to no Master row; kept aside for your review, never discarded.
  • INVALID / MALFORMED — entry missing required fields; kept aside for inspection.

Everything runs inside this unlocked admin session. Your passcode never leaves this browser and is never written to any log or migration report.

Refresh actions

The two refresh buttons are also in the top bar for quick access. Their differences:

  • Refresh from Sheet — dispatches refresh-master-file.yml to re-read the Master Google Sheet and re-encrypt the repo files. Runs automatically every 2 hours. Does NOT bump the cache-buster — viewers with cached JS/HTML will still see the stale copy on their next load. Since Phase 3.5, Save & push in the edit modal auto-dispatches this whenever a Master-backed public field changed, so most of the time you no longer need to click it manually.
  • Force refresh — bumps ?v=mfNN on every V2 script tag so viewers' browsers stop serving the stale copy immediately, and also dispatches refresh-master-file.yml. Use this after any admin change (photo, insights, ORCID, etc.). GitHub Pages typically redeploys within ~30–90 seconds; then hard-refresh the public dashboard.

Rule of thumb: if you just edited the Master Sheet directly and can wait a couple of minutes, use Refresh from Sheet. If a viewer (including you) is looking at a stale public card right now, use Force refresh.

Research insights editable · paste JSON
Canonical shape: { keywords: string[], summaryHtml: string, summaryFormat?: "html" | "plain", sources?: [{title, url, publicationId?}] }.

Auto-normalised on save — paste ChatGPT or Claude output directly, the admin will fold it into the canonical shape:
  • summary → summaryHtml (ChatGPT default)
  • plainEnglishSummary / plain_english_summary → summaryHtml
  • research_keywords / researchKeywords → keywords
  • scholar_id, name (paste envelope) are accepted quietly — used for the Admin log but not persisted onto the record.
  • summary_format / summary-format → summaryFormat
  • Outer name wrapper (e.g. { "Veitayaki, Joeli": { … } } from Claude / V1-style pastes) is auto-unwrapped; the wrapper string is preserved as canonicalName.
  • Unknown top-level keys (e.g. scholar, notes) are dropped with a warning in the Action log — never persisted.
  • summaryFormat auto-detects html vs plain from the content when omitted.
  • Inline links inside summaryHtml: only <a href="http(s)://…">, <em>, <strong> are rendered on the public card. Everything else is escape-encoded for safety.
  • Sources accept either full objects {title, url} or bare URL strings.
