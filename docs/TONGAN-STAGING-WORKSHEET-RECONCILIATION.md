# Tongan Staging — Worksheet Reconciliation

Prepared 2026-09-01. This document is a required deliverable of the Integrated Rebuild directive ("reconcile the newly created tables with the existing Review Queue, Cultural Affiliation Evidence Audit and Part-Tongan worksheets... Do not merge, rename, delete or repurpose those existing worksheets"). It applies to the **backup Sheet** (`1XTbiKazab-2WWJmkqjJ6AIWvymBL5-6Jj8EsHXYcXWs`), which is a full copy of the live Master Sheet plus 12 new tabs added for the integrated rebuild. No existing worksheet was renamed, merged, or repurposed — all 12 new tabs are additive.

## Existing worksheets — untouched, distinct purposes

| Worksheet | Purpose | Relationship to the new system |
|---|---|---|
| **Review Queue** ("Roster Review Queue") | Tracks candidate scholars who are **not yet promoted** into the main `Scholars` sheet, pending heritage-verification research. Columns: Scholar ID, Scholar Name, Gender, Review Status, Review Notes, Roster Tier, In Core Roster?, Source Basis, BibTeX Author Match, BibTeX Author Occurrences, Name Variants/Aliases. | **Unrelated.** This is a *roster-promotion* queue (should this person be added to `Scholars` at all?), not a data-correction queue. The new `Public Update Submissions` / `Submission Field Changes` tables only ever reference scholars **already present** in `Scholars`. Nothing in the new system reads from or writes to Review Queue. |
| **Cultural Affiliation Evidence Audit** | Evidence trail for the lineage/estate/village **sub-fields** already on `Scholars` (Estate/Chiefly Affiliation, Kāinga, Self-identified Affiliation), added 2026-08-28. Explicitly does not infer affiliation from village/surname/title resemblance. | **Distinct but adjacent.** This audits evidence for specific *cultural-affiliation field values*. The new `Identity Authentication` workflow is a separate, higher-level **Indigenous-identity status gate** (Candidate → ... → Verified/Rejected) for the whole scholar record, with its own `Identity Evidence` table using the same non-inference principle (see Weak-Proxy Flag Check) but a different schema and a different decision object (dual-authenticator Verified/Rejected outcome vs. per-field evidence notes). The two are complementary, not duplicates: Cultural Affiliation Evidence Audit can be cited as one *input* into an Identity Authentication case's evidence, but the two tables are never merged. |
| **Part-Tongan** | Separate roster for scholars classified as part-Tongan under Ron's current analytical definition; excluded from the main `Scholars` sheet. | **Not touched.** The new Identity Authentication workflow is scoped to the main `Scholars` roster only. Whether/how Part-Tongan scholars should eventually get their own Identity Authentication cases is an **open design question already flagged in the v2 implementation plan** and is explicitly not resolved by this build — no code in `tongan-staging-writeback.gs` reads or writes the Part-Tongan tab. |
| **Change Log** (5 columns: version / date / change / scope / source) | The pre-existing, simple direct-edit log used across all worksheets in the Master Sheet (not specific to Scholars corrections). | **Kept for its existing purpose**, unchanged. It is distinct from the new `Change Audit Log` (see below) and neither replaces nor is replaced by it. |

## New worksheets added this build (12 tabs, backup Sheet only)

| Worksheet | Purpose | Distinct from |
|---|---|---|
| `Admin Users` | Role directory (Owner/Researcher/Authenticator) gating every `api*` server call. | New — no prior equivalent existed (the live admin used a single hard-coded `APPROVED_ADMIN_EMAIL`). |
| `Public Update Submissions` | One row per public "Update info" form submission: submitter identity claim, scholar, overall status, counts. | Distinct from Review Queue (roster promotion) — this is post-hoc correction of an existing scholar's record. |
| `Submission Field Changes` | One row per individual field proposed for change within a submission, with snapshot/proposed/decision/conflict columns. | New; no prior per-field correction ledger existed. |
| `Submission Reviews` | Audit trail of each Authenticator/Owner review action taken on a submission. | New. |
| `Change Audit Log` | Append-only ledger of every canonical field write to `Scholars`/`Positions`/`Graduate Degrees`, regardless of origin (direct edit, submission apply, rollback), with old/new value and actor. | **Richer and broader than** the existing `Change Log` tab — `Change Log` is a manual/direct-edit note; `Change Audit Log` is a structured, submission-linked, rollback-capable ledger written only by `_appendAuditLog_()`. Both are kept; neither is deprecated by this build. |
| `Identity Authentication` | One row per scholar's current Indigenous Tongan identity status (Candidate → ... → Verified/Rejected) and case metadata. | Distinct from Cultural Affiliation Evidence Audit (see above). |
| `Identity Evidence` | Evidence items attached to an Identity Authentication case, with an explicit weak-proxy keyword flag (never auto-inferred). | Distinct from Cultural Affiliation Evidence Audit — different schema, scoped to the identity-status gate, not to individual lineage sub-fields. |
| `Identity Decisions` | The dual-authenticator decision record: Authenticator 1 / Authenticator 2 outcomes, conflict escalation flag, Owner resolution. | New — implements the hard-constraint requirement that Verified/Rejected requires two distinct approvers. |
| `Identity Status History` | Append-only status-change history for each Identity Authentication case. | New. |
| `Second Review Requests` | Optional second-authenticator review requests for ordinary (non-identity) submission reviews. | New; distinct from the *required* dual-authentication on Identity Decisions — this is an optional collegial check on regular field-correction reviews. |
| `Uploaded Submission Files` | Metadata for files (e.g. photos) attached to a public submission, tracked from quarantine through approval. | New. |
| `Scholar Media` | Canonical approved-media registry per scholar (e.g. approved photo references), separate from the quarantine folder. | New. |

## Summary

No existing worksheet's purpose, schema, or content was altered. Every new table added for the integrated rebuild is additive and serves a workflow (public submission intake, dual-authenticator identity gating, audit/rollback, admin-role management) that did not previously exist. Where a new table is topically adjacent to an existing one (Identity Authentication vs. Cultural Affiliation Evidence Audit; Change Audit Log vs. Change Log), the tables are deliberately kept separate because they serve different questions ("is this scholar Indigenous Tongan by evidence-based dual approval?" vs. "what is the evidence for this specific lineage field value?"; "what changed and can it be rolled back?" vs. "a free-text version/date/change note").
