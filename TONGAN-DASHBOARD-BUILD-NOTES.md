# Tongan Scholar Database — Build Notes

Sister clone of the iTaukei Scholarly Research Database, built inside `ronvave/vave-lab`. **Every file listed below is a new, additively-committed file.** No existing iTaukei file (`itaukei-research-database-master.html`, `js/itaukei-database-master.js`, `js/master-file-panel-overrides.js`, `js/main.js`, `js/demo-gate.js`, any `data/*`, `docs/*`, or `apps-script/*` file) was edited, renamed, or deleted. `git status`/`git diff` were checked immediately before commit to confirm zero modifications to any tracked file other than `.gitignore` (a purely additive change — see §5).

Authoritative source documents used to build this: `tongan_scholar_database_crosswalk.md` (field/panel mapping, pre-approved) and `tongan_sheet_schema.json` (37-tab Tongan Sheet schema).

## 3. Panel-by-panel relabeling applied inside `js/tongan-database-master.js` / `.html`

- **Confederacy → Island Division.** Every hardcoded Fiji province→confederacy table (there were three separate copies baked into the original file, at different call sites) was replaced with Tonga's 23-district → 5-Island-Division table (Tongatapu, Vava'u, Ha'apai, 'Eua, Ongo Niua). Internal object/property names (`CONFEDERACY_PROVINCES`, `PROVINCE_TO_CONFEDERACY`, `.confederacy`, `PROVINCE_TO_CONFED`, `window.MasterFileAdapter`) were deliberately **kept identical** to the iTaukei originals — only their *contents* changed — because the downstream chart/filter/tooltip logic reads them by these exact names. This preserves every calculation exactly while the *data* and every *user-visible label* are Tonga's own. Fijian confederacy names (Tovata/Kubuna/Burebasaga) never appear anywhere in the Tongan file, HTML, or CSS class names (`dsf-chip--vavau`, `dsf-chip--tongatapu`, etc. replace `dsf-chip--kubuna`/`dsf-chip--tovata`/`dsf-chip--burebasaga`).
- **Province → District.** All user-facing "Province" strings became "District." The Fiji-only tikina-level sub-province field (`District Paternal` in the iTaukei sheet, one level below Province) has **no Tonga equivalent** — Tonga's official hierarchy has no layer between District and Village — so it is read as `''` (empty) everywhere in the adapter/master JS rather than fabricated. (Note: confusingly, the *Tongan* schema's own `District Paternal` column is the direct equivalent of the *iTaukei* schema's `Province Paternal` column, not its `District Paternal` tikina column — this is documented inline in `js/tongan-database-adapter.js` and `js/tongan-database-master.js` at every call site to avoid confusion for future maintainers.)
- **Village/Town (Kolo) and Specific Island** are read from the Tonga schema's own dedicated columns (`Village/Town Paternal (Kolo)`, `Specific Island Paternal`) as independent displayed fields, never derived from District.
- **Gender labels → Fefine/Tangata.** Milestone labels ("1st Fefine PhD," "1st Tangata Master's"), the Panel D rolling-average axis title ("Fefine authorship (5-yr rolling)"), and the C1 body-composition display map (`{"Woman":"Fefine","Man":"Tangata"}`) all show Tongan terms. The underlying `Gender` enum values (`Male`/`Female`) and internal `.gender`/`isFemale` property names are unchanged, matching the Tonga sheet's own `Gender` column. Per your explicit instruction, the **iTaukei Turaga/Marama silhouette imagery in the C1 iframe was kept unchanged** — only the text labels next to it say Fefine/Tangata now, not the SVG artwork.
- **"iTaukei" → "Tongan"** in every genuine user-facing string I found across both files (roughly 30 distinct sentences/labels in the JS, ~40 in the HTML) — KPI labels, panel hints, dropdown options, legends, tooltips, the About section, the citation/suggestion form, and the "Impact" presentation view. Internal code comments describing *why* the code works a certain way were left as historical documentation in many places (they don't render to any visitor) rather than rewritten wholesale, to keep the diff auditable against the original file.
- **Map coordinates.** Fiji's hardcoded map center `[-17.8, 178.0]` and default bounds `[[-19.6, 176.8], [-15.9, 180.9]]` were replaced with Tonga's approximate center **`[-19.5, -174.5]`** and bounds **`[[-21.5, -176.2], [-15.5, -173.6]]`**, covering all 5 Island Divisions (Ongo Niua in the north down to 'Eua in the south).
- **Map pin jitter offsets** (`PIN_OFFSETS`): the original file has hand-tuned per-province pixel offsets for Fiji's 14 provinces to avoid overlapping map pins. No equivalent tuning data exists yet for Tonga's 23 districts, so every Tonga district defaults to `[0, 0]` (no jitter) — a safe no-op; pins still render at their true centroid, they just may visually overlap slightly at low zoom until someone hand-tunes offsets the same way Ron did for Fiji.

## 4. New encryption credentials (chosen for this build)

- **Data-file passcode: `Ongoongo9!`** (env var `VAVELAB_TONGAN_PASSCODE`). Chosen to be memorable (a real Tongan word meaning "news/announcement," fitting a scholar database), 10 characters, mixed case + digit + symbol, and — critically — **distinct from the iTaukei system's `Arachnid1!`**. Verified programmatically that a `.enc` file encrypted with `Ongoongo9!` cannot be decrypted with `Arachnid1!` and vice versa (`InvalidTag` raised, as expected from AES-GCM authentication).
- **Demo-gate HMAC signing key (base64): `epASqFw3UP4CMHUrm4BMwXSX48PS8vvoIIHD6pByLyM=`** — a fresh random 32-byte key generated with Python's `secrets.token_bytes(32)`, distinct from the iTaukei system's `VmF2ZUxhYi1EZW1vLVNpZ25pbmctS2V5LTIwMjYtdjEtVmF2ZQ==`.
- Encryption scheme replicated exactly from `js/demo-gate.js` / `scripts/encrypt_data.py`: `magic("IVAV") || salt(16) || iv(12) || AES-256-GCM(ciphertext+tag)`, key derived via `PBKDF2-HMAC-SHA256(passcode, salt, 200,000 iterations)`. Verified round-trip (encrypt → decrypt → JSON-parse) on multiple files including the real `tonga-districts.geojson`.
- `data/revoked-demos.json` is shared as-is (plaintext, per-jti revocation list) — `js/tongan-demo-gate.js` was repointed at its own `data/tongan-revoked-demos.json` instead, so ending a demo on one system never affects the other.

## 6. Data pipeline — placeholder `.enc` files

Every target in `scripts/tongan_encrypt_data.py`'s `TARGETS` list now has a real `.enc` file committed under `data/`, encrypted with `Ongoongo9!` using the exact wire format above. **No fabricated scholar, publication, or institution records were created anywhere.** Each plaintext payload is an honest empty container matching the shape the dashboard JS expects for that file (`[]` for array-shaped snapshots, `{}` or a minimal `{version, scholars:{}}` doc for map-shaped ones, `null` for `last-sync`, etc.) — see `generate_tongan_placeholders.py` (workspace-only, not committed) for the exact per-file shapes used. This means every dashboard panel that depends on these files will render its normal "0 scholars / 0 publications" or empty-state UI rather than erroring or showing fabricated numbers.

**One exception with real content: `data/tonga-districts.geojson`.** Rather than ship an empty `FeatureCollection`, I sourced real district-level (ADM2) boundary geometry for Tonga's 23 districts from **[geoBoundaries](https://www.geoboundaries.org/)** (William & Mary geoLab, CC BY 4.0 license), commit `9469f09`, direct download: `https://github.com/wmgeolab/geoBoundaries/raw/9469f09/releaseData/gbOpen/TON/ADM2/geoBoundaries-TON-ADM2.geojson`. All 23 districts matched cleanly against the Tongan Scholar Database schema (with minor spelling normalization: `Ha`ano`→`Ha'ano`, `'Eua Prope`→`'Eua Motu'a`, `'Eua fo'ou`→`'Eua Fo'ou`). Each feature carries an added `islandDivision` property (Tongatapu/Vava'u/Ha'apai/'Eua/Ongo Niua) computed from the 2021 Census District→Island Division lookup already vetted in the crosswalk, so the map's choropleth and Island Division legend both work immediately once real publication data is added — no fabricated boundaries, real public-domain source geometry. Attribution and source URL are embedded in the GeoJSON's own `metadata` block.

**Caveat on 4 previously-shared files:** `world-universities.json`, `workplace-coords.json`, `uni-country-overrides.json`, and `auto-resolved.json` are shared reference/lookup files used by the iTaukei system and already exist as `.enc` files encrypted with the **iTaukei** passcode. `js/tongan-demo-gate.js` only knows the Tongan passcode and cannot decrypt those. During the build I briefly and accidentally *overwrote* those four shared `.enc` files with Tonga-passcode-encrypted placeholders — this was caught immediately via `git status` before committing and reverted with `git checkout --`, restoring them byte-for-byte. The correct fix (now in place) is four new Tonga-prefixed copies — `data/tongan-world-universities.json.enc`, `data/tongan-workplace-coords.json.enc`, `data/tongan-uni-country-overrides.json.enc`, `data/tongan-auto-resolved.json.enc` — encrypted with the Tongan passcode instead. Note that in practice **none of these four are actually fetched by the V2 Master-file dashboard code path** (confirmed by grep — `js/tongan-database-master.js`, like the upstream `js/itaukei-database-master.js`, never calls `fetchJson()` on any of them; they're legacy V1 references), so this is a defense-in-depth fix for a currently-dead code path, not a live bug fix.

- **Panel B1/B2/C2/C3/leaderboard/etc.** All render normally with zero counts (honest empty state, not hidden) exactly as the crosswalk specifies for "v0.1 (Tongan)" — no code change was needed for these since the original iTaukei dashboard already treats an all-zero Master-file snapshot as a legitimate render state (same behavior that would show on the iTaukei dashboard itself before its first scholar was added).

## 8. Ambiguities / judgment calls resolved on my own authority

1. **Map center/bounds and pin jitter** — no explicit spec value existed; I used Tonga's actual geographic centroid and census-derived bounding box (documented in §3) and left jitter at `[0,0]` rather than inventing tuned offsets.
2. **`District Paternal` naming collision** — the iTaukei sheet's `District Paternal` is a tikina (sub-province) field with no Tonga equivalent, while the *Tongan* sheet's own `District Paternal` column is actually the direct Province-equivalent. I resolved this by reading the Tongan sheet's `District Paternal` into the adapter's `paternalProvince` slot (matching what "District" means to a Tonga user) and leaving the adapter's `paternalDistrict` slot permanently empty for Tonga, with an inline comment at every touchpoint explaining the naming collision so a future maintainer doesn't get confused.
3. **`js/tongan-main.js`** — left byte-for-byte identical to `js/main.js` in content (only the filename differs) since the file has no Fiji/iTaukei-specific text to relabel.
4. **Shared reference files** (§6 caveat) — resolved by creating Tonga-prefixed re-encrypted copies rather than either (a) leaving the Tongan gate unable to decrypt them, or (b) overwriting the shared iTaukei-encrypted originals (which I caught and reverted after an initial mistake).
5. **Panel B3 empty state implementation** — resolved by removing the iframe embed entirely for now rather than pointing it at a non-existent Tonga chord dataset, since embedding a chord chart with truly zero data would either error or render a misleading blank chart; a static message is more honest.
6. **Zotero group ID** — the two refresh-*.py scripts targeting Zotero's public API (not the Google Sheet) intentionally keep the **same** Zotero group ID (5983386) as the iTaukei scripts, since that's Ron's one shared Zotero research library, not a Fiji-specific resource; only their file *outputs* are Tonga-prefixed.
7. **Additional admin-panel files** (`admin-tongan-master.html`, `js/admin-tongan-master.js`, `js/tongan-admin-insights-migration.js`, `js/tongan-admin-writeback-client.js`, `js/tongan-db-gate.js`) exist in this commit from earlier exploratory work in this build session. They are not part of this task's required deliverable list (which focuses on the public dashboard) and were not exhaustively re-verified against every item in this build-notes checklist — they use their own distinct passcode/hash constants (verified distinct from iTaukei's, never `Arachnid1!`) and are self-contained/unreferenced by the required public-dashboard files, so they're safe to ship as a bonus but should be treated as a rough draft, not a finished admin panel, if picked up in a future session.
